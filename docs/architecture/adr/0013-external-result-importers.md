# ADR-0013 External tool result importers
Status: Proposed — build later (not scheduled; revisit after Phase 9)
Context: Customers already run performance and security tools (k6, JMeter, OWASP ZAP, …) and want one report, one history, one set of gates and sinks across functional and non-functional results. The reference framework shipped k6/ZAP wrapper scripts, but k6 is AGPL-3.0 and cannot be bundled or depended on (ADR-0010), and running these tools is not core's job.
Decision: Add an entry-point group `paccaassure_taf.importers`. A `ResultImporter` plugin reads a tool's native output file (e.g. k6 `--summary-export` JSON, JMeter JTL, ZAP JSON report) and converts it into standard `TestResult`s (layer `perf` or `security`, thresholds/alerts as steps, metrics as step outputs) that join a run via `pataf results import --tool <name> --file <path> --run <id>`. Core never invokes or bundles the external tools; customers run them however they like.
Consequences: Non-functional results appear in the report, history, trends, gates and sinks with no special cases. Adds `perf` and `security` to the layer tag vocabulary when built. Each importer is optional (its own extra or a separate package) and must pass the license allow-list; parsing a tool's *output format* does not require depending on the tool.
