# ADR-0015 Config loader with provenance (pydantic-settings dropped)
Status: Accepted (confirmed at the Phase 1 review, 2026-09-25)
Context: Config is layered (core defaults → app packs' `pataf.app.yaml` → `pataf.variant.yaml` → `envs/<env>.yaml` → `PATAF_*` env vars → CLI; LAYERING). `pataf config show --resolved` must print the **source of every value**, and a validation error must name the file/variable that set the bad value. pydantic-settings merges its sources internally without per-value provenance, and its fixed source priority (init kwargs > env > …) does not match ours, so we would have fought it rather than used it.
Decision: `paccaassure_taf.core.config` implements a small loader: read each layer (YAML files; `PATAF_A__B` env vars → `a.b`, JSON for lists/objects; CLI dotted overrides), deep-merge with a provenance map (dotted key → layer name), then validate the merged tree once with plain pydantic v2 models (`PatafConfig`, `extra="forbid"` so typos fail with their source). `pydantic-settings` is removed from the dependencies and the Stack line.
Consequences: Errors read "logging.level: Input should be … (set by envs/qa.yaml)". Values for sensitive keys are never echoed in errors. Unknown `PATAF_*` variables and unknown keys fail fast (typo detection). App-pack/variant config sections are added in Phase 2 through a plugin-registered section model instead of relaxing `extra="forbid"`.
